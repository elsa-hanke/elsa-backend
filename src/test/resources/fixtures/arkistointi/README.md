# Pre-async SÄHKE regression fixtures

These five XML files were captured using `SahkeMetadataBuilder` and
`SahkePakettiBuilder` from commit
`c76d6d293c50bec7880be8e6eb998c2c1002aa4f` (the parent of `98453773`, which
introduced `SahkePerson`). They are independent expected results, not XML
generated by the current implementation during the regression test.

`SynchronousArkistointiLegacyRegressionTest` defines the synthetic input:
study right 4101, documents 5101 onwards, fixed names with Finnish/Swedish
characters, birth date, specialty, student number, reviewer and approver.
Document bytes come from `fixtures/valid.pdf`. The clock is fixed to
2024-12-31; review and approval dates are deliberately different. Configuration
comes from `ArkistointiTestData.createApplicationProperties()`.

Capture covered Helsinki VALMISTUMINEN, SOPIMUS and KOEJAKSO, and Tampere
VALMISTUMINEN and KOEJAKSO. For each scenario, XML captured inside the ZIP and
as separate metadata bytes was identical. No university archive was contacted.
The metadata DTOs were unchanged between that commit and capture.

To reproduce the baseline, temporarily compile the two historical builders
under distinct test-only class names, reusing the unchanged metadata DTOs and
the original seven request arguments. Use the regression test's input and
mocked `LocalDate.now()`, then capture the ZIP's `sahke.xml` (or metadata bytes).
The temporary capture classes were removed after generating these fixtures.

The regression test compares XML structure, attributes, element order and leaf
text, ignoring formatting indentation between elements. It also checks the legacy ZIP filename, exact entry list and
every embedded PDF against the input bytes. ZIP container timestamps are not
part of the contract. Do not regenerate these files from the current builder
merely to make a failing test pass; review any intended contract change first.
